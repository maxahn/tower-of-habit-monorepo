ADR-0001 conflict: The route handler still checks voluntaryAbsenceDaysUsed + days > 28 — the budget-based mechanic that ADR-0001 (shield-based absence) decided against. Extracting this into a module isolates the migration to one place.

Problem: The absence declaration is 60 lines of domain logic embedded in a route handler — date validation, budget arithmetic, dormancy timing, two DB writes — with no module to test independently.

Solution: An absence module with declareAbsence and cancelAbsence as the interface; the route handlers become 3-line adapters.

  • ✦ Locality: absence rules in one place
  • ✦ Route handler loses 50+ lines of business logic
  • ✦ Testable without HTTP scaffolding
  • ✦ ADR-0001 migration isolated to one module

6. Deepen entry logging into a domain module

Strong

Before

Two entry-logging paths. The route handler owns membership side-effects the DB path skips.

After

logEntry() callers — same 5-line shape
Entry Logging Module — interface

logHabitEntry(tx, userId, habitId, body, now)

→ { entry, qualifies, created, source, woke }

resolve day boundary

resolve localDate + gap-fill

check qualification

write entry

update membership counters

dormancy wake-up

compute source

One module, one interface. Membership effects can't be forgotten.

Parallel-path risk: The DB-layer logEntry() resolves day boundaries and writes entries, but does not update lastQualifyingDate or fire the dormancy wake-up. The route handler's recordEntry() path does, but only because those 20 lines were added inline. Any new caller of either path will silently miss one side or the other.

Problem: The POST /entries route handler is an 88-line pipeline that orchestrates seven domain concerns — day-boundary resolution, gap-fill probing, qualification, entry write, lastQualifyingDate bookkeeping, dormancy wake-up, and grace-window classification — paralleling the DB layer's logEntry() which does the first four independently but skips the membership effects.

Solution: One logHabitEntry(tx, userId, habitId, body, now) interface that internalizes the full pipeline. The route handler becomes a 5-line adapter.

  • ✦ Locality: "how an entry is logged" in one place (today it's split across 3 files in 2 packages)
  • ✦ Safety: dormancy wake-up and lastQualifyingDate can't be forgotten by a new caller
  • ✦ Route handler: 88 lines → ~5
  • ✦ Leverage: mobile offline queue, future bulk-import, and tests all hit one seam
  • ✦ Delete: sourceOf() moves internal; gap-fill duplication collapses

Top recommendation

Start with Candidate 1 (notification dispatch) — it's the fastest win: two nearly identical files collapsed into one, clear before/after, zero risk. Then Candidate 3 (absence module) — it directly enables the ADR-0001 shield migration by giving it a home. Then Candidate 2 (evaluation orchestration) — highest impact, most-changed area, route-handler duplication is a real source of bugs.

Suggested order: 1 → 3 → 2. Candidates 4 and 5 are worth exploring after the first three land.
